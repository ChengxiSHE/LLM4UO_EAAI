# ARK 在本研究中的实际边界

本机 ARK 的源码、README_zh.md 和 docs/CODEX_LOCAL.md 表明，它通过 OpenHands/LiteLLM 编排 researcher、planner、coder、experimenter、writer、reviewer，提供工作目录、检查点、监控、实验与论文组织能力。它不会自行保证建模答案正确、方法新颖或试验设计有效。

到目前为止，LLM4OR-EAAI 的研究方案、数据修订、求解器、独立评价和验证主要由用户与 Codex 交互完成。使用 ark-base 环境不等于使用 ARK 的研究引擎；不能将目前的工程进展算作 ARK 自动研究的成果。

本次决定：正式实验使用本项目的冻结运行器，不再套入 ARK 的自主研究循环。否则另一个代理可能修改方法、提示和测试方案，既增加无法归因的变化，也绕开当前的唯一请求账本。ARK 的 max_iterations、界面费用估计、conda 环境均不是本项目的费用硬上限或任意代码安全沙箱。

ARK 的可用位置是外层：在已经批准的固定命令外做任务状态管理，以及实验结束后读取脱敏汇总来组织图表、文献和稿件。是否值得使用，应看它是否省下重复劳动；不是本研究成立的前提，也不是 LLM4OR 方法的一项贡献。本次未启动 ARK 研究代理，授权范围不包含其额外模型调用。

固定入口：本项目 scripts/run_formal.py。默认只预检；明确批准后才使用 --execute-approved。运行器自行管理唯一账本、断点和输出，不依赖 ARK。运行状态在 results/private/formal_v1_20260831/；只向论文流程提供评价汇总，不提供密钥、未冻结测试反馈或原始答案文件。不要把研究目录移回 ARK 安装目录。
