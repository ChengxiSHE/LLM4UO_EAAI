# 正式实验结果复核

更新：2026-10-03。结论状态：**本文件中的 v3 修正版评价可用于历史对照；原始 `evaluation.json` 不得继续用于逐单元资格、失败原因或配对统计。v3 不支持原方法提升，但后续独立 V9 Text2Opt 确认已支持一个范围明确的新方法提升。**

## 后续确认性证据

v3 的负结果没有被改写。经过 v4–v8 的机制诊断后，V9 将六类结构化公开文本编译为审计模板并以 exact solver 求解，失败时保持同一 Base。V9 在冻结的 401 条 Text2Opt 确认集上完成预注册评价：400 条配对记录中 Base 为 200/400（50.00%），V9 为 259/400（64.75%），提高 14.75 个百分点；59 次纠正、0 次退化，单侧精确 McNemar `p=1.7347e-18`，六类提高、一类持平、零类下降。全部预注册门槛通过。

因此，项目现在可以使用“benchmark formulation accuracy 显著提高”的表述，但必须同时限定数据集、比较对象与操作定义。该 accuracy 指最优状态及目标值与公开答案一致，不证明变量、约束或可行域完全语义等价。V9 的完整统计、设计和局限见 [`V9_CONFIRMATORY_RESULTS.md`](V9_CONFIRMATORY_RESULTS.md)；下面其余内容仍专门记录 v3 正式矩阵的复核。

## 结论

本次正式实验没有提供“Full 或自进化流程提高建模质量”的可靠证据。在冻结的 522 条 held-out 记录上，每种方法有 4,698 个题目×重复×预算单元：Base、B、SolverRepair 的公开标签代理匹配率均为 51.852%，A 为 51.831%，SimpleAB 与 Full 均为 51.916%。最高与 Base 的差距仅 0.064 个百分点，同时 Full 的逻辑 token 为 Base 的 2.83 倍。

配对差异只集中在极少数题目。Base→A 和 SimpleAB→Full 没有任何共同可用单元发生结果变化；Base→B 与 Base→SolverRepair 都是 2 个改善、2 个退化，净变化为零；A→SimpleAB 的 4 个净改善来自 2 道题，B→SimpleAB 的 6 个改善和 2 个退化来自 4 道题。一个题目在多个预算和请求命名空间中重复出现，因此不能把 4,698 个单元当作相互独立样本，也不能据此声称统计显著提升。

流程进化本身没有改变最终程序。九条搜索流的最终程序都与各自初始程序相同；18 次 gate 中 16 次没有选出候选，2 次因基础设施缺项无法完成。B 与 SolverRepair 的最终程序相同，SimpleAB 与 Full 的最终程序也相同，这与它们几乎完全相同的结果一致。

## 评价缺陷与修复

原评价程序的缓存键只绑定最终模型、输入和参考，没有绑定推理记录状态与错误。若正常记录和失败记录共享相同最终模型，就可能错误复用评分；反过来，模型返回非法 JSON 或截断输出后，同一缓存结果的后续使用者也会被包装成基础设施中断。

修复后的 `formal-evaluation-v2` 把记录状态、错误、轨迹错误、最终模型、输入和参考都纳入缓存绑定，并把非法 JSON／不完整响应保留为模型输出失败，仅把真实传输或全局错误排除出可用评价。修正改变了 2,898 个单元的评价对象，其中 2,322 个资格标记和 2,262 个代理值发生变化；106/108 条分层配对汇总的分母或计数随之改变。由于受影响单元在方法间大体对称，最大净效应变化约 0.0046 个百分点，研究主结论没有反转。

运行阶段写出的 3,995 个 `infrastructure_unavailable` 记录中，修正版识别出 2,926 个真实传输失败，以及 1,069 个非法 JSON／不完整响应等模型输出失败。后者现在保留在完整分母中并按不匹配处理。原始文件保留为缺陷证据；后续分析统一使用私有运行目录中的 `evaluation_v2.json`，其 SHA-256 为 `30be6c1d9f72ac198eb61bddeba751a7444d555992c4ed6bf18dc78a8bcf2c60`。

## 数据质量和可解释性限制

真实传输缺失不是随机分布：OptMATH-Bench 为 1,480/8,964（16.51%），MAMO ComplexLP 为 1,240/10,962（11.31%），ComplexOR 为 138/1,998（6.91%），IndustryOR 为 68/5,400（1.26%），NL4Opt 与 OptiBench 为零。最高预算档的传输缺失也更多。共同可用配对避免把一侧中断直接当作另一侧优势，但结论只适用于双方都可用的单元；完整分母率则同时混合模型质量和服务可用性。

公开目标值／状态匹配是本项目预先定义的 benchmark formulation accuracy，而不是完整语义等价。修正版评价中共有 30,795 个匹配、16,661 个不匹配、16,960 个无受支持最终模型，以及其他未决状态。576 个带 `independent_model_audit` 的可评价单元全部为 `formulation_check=unsupported`，且都没有可用的 objective-match 结果；其中 54 个仅确认状态一致。因此，v3 的这些百分比可以作为公开答案准确率报告，但不能证明任何方法生成的约束、变量域或业务语义完整正确。

三个 replicate 是独立请求／缓存命名空间，服务商没有确认随机种子；温度为零也不能保证它们构成 IID 重复。预算档和 replicate 对同一道题产生重复观测。正式统计应先在题目或保守语义家族层面聚合，并明确处理缺失；当前稀少的差异不足以支持方法优越性检验。

## 论文和后续工作的约束

1. 任何结果表、图或论文草稿都应从 `evaluation_v2.json` 或公开的聚合验证清单生成，并标注 `formal-evaluation-v2`；原始 `evaluation.json` 只能用于缺陷追踪。
2. 当前可以报告：全量运行完成；代理结果方法间近似持平；Full 没有超过 SimpleAB；流程进化没有产生程序更新；复杂流程消耗显著更多 token。
3. 当前不能报告：Full 显著提升、语义反馈提高真实建模准确率、进化成功学习到更优工作流、三个请求命名空间构成统计独立重复。
4. 若要检验核心研究假设，下一阶段应优先建立按语义家族分层的专家／可执行 formulation gold，并针对真正发生方法分歧的少量题目做盲审；随后再决定是否需要一次更小、能产生实际程序变更的定向实验。
