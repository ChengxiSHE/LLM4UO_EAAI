## 1. 一句话定义

在固定基础模型、角色提示、原子工具和独立评价器的条件下，利用候选模型的可执行语义差异构造有来源的教学反馈，自动进化一个**带条件的验证—修复程序**：teacher 组织证据与开发修复分支结果，修复 gate 控制当前题修改，进化 gate 决定程序更新是否用于后续任务。

方法对象是程序策略，而不是模型权重或某一道题的答案。单题中的状态变化称为 adaptation/repair；跨题更新可复用程序才称为 self-evolution。仅手写规则、把反思存入文本库或从固定列表中选流程，不能单独证明这里的程序进化已经发生。

## 2. Harness 的精确定义

运行系统写成 S_H = K(F_theta, H)：F_theta 为冻结 LLM，K 为固定执行内核，H 为可进化控制程序。

    H = (G, Gamma, Sigma)

- G：验证—修复的有界控制流图。节点调用固定操作；边表示继续、回退、回滚或停止。
- Gamma：边的触发条件和互斥/优先规则，只引用白名单中的运行时证据特征。
- Sigma：修复作用域规则，将错误定位映射到允许修改的模型片段及其依赖闭包。

程序连同固定内核诱导历史依赖策略 pi_H(a | h_t)。h_t 包含题目、当前语义规格和模型、已观察证据、版本与动作历史、剩余资源。真实建模正确性不是控制器可观察的状态。短特征向量只是实现输入，不假设其具有 Markov 充分性。

### 2.1 固定部分与可进化部分

| 组成 | v1 是否可进化 | 明确边界 |
| --- | --- | --- |
| LLM 权重、模型服务、温度、基础角色提示 | 否 | 所有程序版本使用同一配置；角色输入的实例内容会变化 |
| 结构化模型 schema、证据 schema、求解器、原子检查实现 | 否 | 不允许修改求解器结论、检查器定义或数值容差以通过验收 |
| 检查与修复的连接关系、调用顺序、回退位置 | 是，G | 只能在声明的语法和节点数量/循环上限内修改 |
| 何种证据触发何种流程、规则优先级 | 是，Gamma | 不能包含题目 ID、参考答案、benchmark 名称或任意样本文本常量 |
| 单项、关联条款、依赖闭包等修复范围选择 | 是，Sigma | 不得越过内核规定的最大写集合；范围小不等于语义安全 |
| 从固定检查库选择补充检查及其顺序 | 是，属于 G | 不进化任意测试代码；新检查器属于作者工程改动，须另立版本 |
| 必须执行的修改后检查、回滚保护、资源限制、访问控制 | 否 | 不得通过删掉安全检查提高表面成功率 |
| 独立终端评价器、参考答案和标签解释 | 否 | 不以代理自评分替代外部评价，不允许程序改自己的考卷 |

v1 不同时做提示进化、模型微调、自由工具生成和文本经验库扩张，避免无法归因。可另设文本记忆/提示优化基线。进化产物是序列化程序及版本差异；开发轨迹库只为提出修改服务，正式推理不检索开发答案。

### 2.2 固定原子操作与证据接口

初始原子操作库：生成语义规格和模型、条款覆盖检查、变量域/单位/索引检查、受控求解、适用的模型片段反例搜索、局部修复、依赖重检、回滚、停止/未解决。实现使用结构化 LP/MILP 和可信求解器适配器，不执行任意 LLM 生成的 Python。

证据至少包含：类型、来源条款 ID、关联变量/约束 ID、产生证据的工具、当前模型版本、适用前提、可重现残差或测试输出，以及状态 pass/fail/unknown。LLM 推测须标明来源；数值反例只对所用形式化条款有效，不证明条款本身忠实于自然语言。

角色是同一模型的不同调用职责：建模器生成、规格检查器核对、修复器编辑；程序而不是一个无限制“总指挥”决定路由。验证角色不能读取隐藏参考模型，也不假设同模型各角色的错误独立。

v0.2 的 teacher 是固定模型加可信求解工具的教学职责：提出相关条款的备选解释、重放数值差异、输出有来源的局部修复建议，并在开发阶段组织实际配对分支结果。不是强模型替代学生，也不是新的真值来源。基础工具库增加作者实现的双向 LP 见证搜索和目标偏好探测；工具实现固定，H 只学习何时/如何调用。

### 2.3 DSL 与局部修改

第一版采用有限、类型化的领域专用语言（DSL），不接受任意生成代码：

    guard := 白名单证据谓词 | guard AND guard | guard OR guard
    node  := 调用固定操作(类型化参数, 作用域) | 有界分支 | 停止
    patch := 替换一个 guard | 插入/删除/重排一个可选节点
             | 重定向一条回退边 | 替换一种允许的作用域规则

每代主实验只接受一个局部 patch；候选可由冻结 LLM 根据开发轨迹提出，但必须通过 DSL 编译、类型/可达性检查、循环上限、信息访问和内核不可修改性检查。编译器执行规则优先级并提供确定的冲突与缺省处理，不能由执行者临场解释规则。

语法复杂度、候选数和代数在开发阶段固定并记录；不能依照测试集成绩扩大搜索。静态检查能保证的只是表示合法、访问边界和执行有界，不能保证数学建模正确。

## 3. 单题运行：执行已固定的程序，不更新它

1. 同一初始化器从题目生成语义规格、模型与条款映射，保存初始版本。
2. 执行 H 中当前适用的检查，积累带版本的证据。
3. 根据 Gamma 选择动作；若需要修复，由 Sigma 生成写集合和依赖闭包。
4. 修复只提交差异，不直接覆盖当前保留版本；内核强制重新检查修改目标及受影响依赖。
5. 修复必须解决指定证据，并通过仍适用的既有检查。因规格变化而失效的旧测试必须标为失效并重新生成/审查，不能将其静默删除或机械保留。
6. 验收通过后接受新版本，否则回滚；仍无法消除的冲突报告 unknown/unresolved。停止不意味着已证明正确。

以上第 4—6 步的强制保护不能由 H 关闭。可进化的是到哪里找问题、走哪条路径以及在许可范围内修复多大区域。全部调用及补充检查计入资源记录。

## 4. 跨题进化：候选提出、选择、验收和继承

数据先按问题家族跨来源去重，再划分为 D_build、D_select、互不重叠的 D_gate,k 和 D_test。改写/参数变体跟随母题。公共模型预训练污染仍不可据此消除。

### 4.1 数据权限与反馈来源

- D_build：当前程序的运行轨迹；开发评价器可使用参考信息产生终端得分和错误类别。候选提出器读取轨迹与诊断，不接收参考程序或答案作为可写入规则的内容。
- D_select：用于比较和筛选候选，可重复使用但须承认开发选择偏差。与 D_build 具有相同的隔离评价规则。
- D_gate,k：仅用于本代冻结候选与 incumbent 的独立比较。本代选择候选时不能查看该批数据或结果；使用后退役为已暴露开发数据，不能再作为 fresh gate。
- D_test：全部进化和调参结束后，冻结程序进行最终评估；标签由外部评价器持有，不回写任何程序或跨题记忆。

因此方法是**有开发集评价反馈、无模型权重更新的自动程序进化**，不是“无需标签的自我提升”。若只使用目标值匹配或其他代理指标，必须将其称为相应指标的进化，不能自动上升为语义正确性保证。

### 4.2 可执行的进化步骤

    H_0 = 预先定义的固定验证—修复流程
    for k = 1,...,R:
        在 D_build 上运行 H_{k-1}，同时保留成功、失败和退化轨迹
        聚合错误证据、触发条件和终端错误类别
        固定 LLM 提出至多 M 个局部 DSL patch
        静态拒绝不合法、越权、非有界或疑似记忆样本的 patch
        在 D_select 比较完整候选与旧程序，选出一个候选 H'
        锁定候选内容、样本量、随机化方案及检验阈值
        在尚未暴露的 D_gate,k 上配对运行 H' 和 H_{k-1}
        若独立验收通过，H_k = H'；否则 H_k = H_{k-1}
        保存程序差异、所有候选、选择依据、拒绝原因和完整用量
    用冻结 H_R 运行 D_test；不使用测试反馈继续迭代

D_select 主评分是相同运行条件下的终端准确率；持平优先较简单程序，再比较实际开销，不暗中改为质量减成本的奖励。新策略必须重新运行：旧轨迹只覆盖旧策略走过的路径，不能用旧日志冒充新策略的反事实表现。

给最接近基线同等开发标签访问权和相称搜索机会；额外比较随机合法 patch、相同开发数据的文本经验检索、仅调 guard 和完整程序进化。报告进化的总开销，与推理成本分列。

### 4.3 差异反馈与两级 gate 的连接

可行性/偏好见证只证明候选不同。teacher 将其关联到原文条款、变量映射和建议写集合，语义判定可能出错，无法裁定时报告 unknown。修复 gate 检查证据可重现性、目标冲突及关联约束，防止只消灭一个例子却引入已知退化。开发阶段从相同前缀真实运行不同修复路径，经隔离评价形成动作—结果反馈，再更新 G/Gamma/Sigma。跨题更新使用本文件的独立进化 gate；不能用与 teacher 更一致或 D_Q 更低代替终端正确性。详细定义与例子见 SEMANTIC_FEEDBACK.md。

## 5. 理论如何直接规定进化过程

### 5.1 从“策略”到具体程序更新

定义 J(H) = E[Q(Run(H,x))]，Q 是独立评价的终端正确性，期望同时覆盖固定任务分布和模型随机性。评价条件包括统一的基础模型、初始化器、运行上限和工具。

经典策略改进分析研究策略变化与回报变化的关系；参见 [Schulman et al. (2015), Section 2](https://proceedings.mlr.press/v37/schulman15.pdf)。这里不运行 TRPO/PPO，不把其保证移植给 DSL 搜索，也不假设文本编辑距离等同于策略距离。我们针对局部程序修改使用下面的直接分解。

### 5.2 命题 A：触发覆盖率 × 条件净收益

候选 H' 与 H 仅在一个条件分支处不同。在第一次分歧前，二者使用相同程序行为；以共享前缀实现耦合。guard 只读取已经可见的特征；若需要新增一次 LLM 检查来判断条件，该检查本身就算作分歧，不能把其开销或影响藏在公共前缀中。E 表示本次轨迹到达第一次分歧，p = P(E)。没有分歧时整条轨迹相同，包括资源与随机输出；分歧后分别执行两个完整的后续程序。

对二元终端得分，定义：

    g = P(Y'=1, Y=0 | E)    # 新程序纠正旧程序最终失败
    l = P(Y'=0, Y=1 | E)    # 新程序破坏旧程序最终成功

则：

    J(H') - J(H) = p (g - l).

证明：E 不发生时 Y'-Y=0；E 发生时二元变量之差的期望等于上述两个不一致事件概率之差，应用全期望即可。此处 g/l 是整套后续流程的终端比较，不能用“本轮多通过一个检查”替代。

模型随机性存在时 g/l 的各自数值依赖配对/耦合方案，须固定并披露；差值仍对应边际期望差。共享相同初始产物和触发前快照是可实现的机制实验。对称计算两分支的逻辑前缀成本，不能只给候选免费前缀。

对应设计：Gamma 决定 p 和被覆盖的错误类型；G 影响发现与修复的成功；Sigma 与强制保护影响退化。不能认为扩大 guard 必然更好，因为它会同时改变 g 和 l。还须在成功题和未触发题上审计，不能只筛失败题计算“改善”。

这是标准概率推导在程序更新上的应用，不是新发现的通用 RL 定理。成立范围是固定分布和执行条件；不意味着每题、每个 benchmark 或跨分布都改善。

### 5.3 命题 B：独立配对验收控制错误更新

v1 的二元标签 gate 使用预先声明的**单侧精确配对检验**。每个独立问题家族，按预先冻结的抽样规则抽取一个实例/随机重复作为检验单位；所有其他改写和重复只用于诊断，不能当作独立样本。冻结候选与旧程序接受同样的初始化、信息和资源规则。

令 n_+ 为新对旧错的对数，n_- 为新错旧对的对数，m=n_++n_-。在候选总体准确率不高于旧程序的原假设下，不一致对中新程序获胜概率不超过 1/2。条件于 m，单侧 p 值为：

    p_k = sum_{j=n_+}^{m} choose(m,j) * 2^(-m),  m>0;
    p_k = 1,                                  m=0.

该精确二项式构造属于配对比例比较方法，而不是我们的新检验；背景为 [McNemar (1947)](https://doi.org/10.1007/BF02295996)。实现须明确单侧方向，不能误用软件默认双侧结果。

预分配 delta_k = delta/[k(k+1)]。仅当 p_k <= delta_k 且未违反固定执行保护时接受更新。若每代的独立同分布配对家族来自同一目标分布、候选在 gate 前确定、标签可靠、样本量事先固定且没有未计入的多候选检验，则：

    P(至少一次接受 J(H') <= J(H) 的候选) <= sum_k delta_k <= delta.

证明：每一代在历史条件下的错误接受概率至多 delta_k，再用 union bound。它控制的是整个进化过程中的错误接受风险，并不保证一定找到或接受改进，也不保证最终有限测试集成绩逐代上升。

连续/家族平均分不可直接套用二项检验；可预先选用 THEORY.md 的 bounded paired-difference/Hoeffding 规则。不能看结果后挑更容易通过的检验。不满足独立家族/新数据等前提时只能报告经验更新，不宣称上述保证。

样本少、可用新家族不足或退化/纠错对太少时可能没有更新被接受：报告功效、拒绝率与数据消耗，必要时缩减代数或停止。不能反复使用相同 gate，不能把参数变体当作新独立家族来维持“持续进化”。先导 10 题不是本命题的实证验证。

### 5.4 固定验证语义，防止优化代理得分

推理中的约束残差、条款覆盖和求解器状态是证据；开发和测试的独立 Q 才是优化目标。若 gate 使用代理 Q_tilde，上述保证只能针对它。若对所有考虑的程序均能证明 |J(H)-J_tilde(H)|<=epsilon，则真实增益至少为代理增益减 2 epsilon；本方案目前没有这种校准证明。

因此程序可进化“调用哪些检查”，但不能进化“什么被算作正确”、参考答案、容差或验收统计。修改规则会触及错判参考标签时，应作为数据勘误单独审计并保留原协议结果，不能静默调整分母。

## 6. OR 示例：会运行但违反文本条件

以下仅用于说明操作，不是已测量的 benchmark 结果。

题目要求每个订单分配给且仅分配给一台机器。当前模型使用 0<=x_ij<=1 的连续变量，求解器给出 optimal。独立条款抽取指出不可拆分要求，变量域检查产生 domain_mismatch 证据。

旧程序：求解成功 -> 输出；或针对非 optimal 才调用通用代码修复。

候选 patch：在“求解成功且存在关联明确的 domain_mismatch”时，插入条款复核 -> 变量域/关联约束的局部修复 -> 依赖重检 -> 重新求解。整数化只适用于复核确认的不可拆分语义；不把“分配”关键词当作所有场景都要整数变量的规则。

进化的差异是多了一条条件分支及其动作/作用域，不是保存这道题的整数答案。开发选择同时包括可拆分与不可拆分问题，检验候选是否错误地把合法连续模型整数化。验收评价完整建模结果；不能把“整数变量变多”当作改进奖励。

如果该 patch 由作者手写，其实验只证明该规则作用；只有自动提出、选择、验收并在后续代继承修改，才证明程序自进化机制发挥作用。

| 理论/定义 | 强制的方法设计 | 直接实验 |
| --- | --- | --- |
| pi_H 是明确程序策略 | 保存 G/Gamma/Sigma 与每代 diff | 固定流程、只改 guard、完整图修改比较 |
| Delta J=p(g-l) | 记录触发前快照，运行完整配对分支 | 触发覆盖率、纠错/退化、宽/窄 guard、局部/全量重写 |
| 独立更新风险控制 | 先选定候选，再用 fresh family gate；误差跨代分配 | 有/无 gate，验收与拒绝记录，数据需求与功效 |
| 代理质量不等于真实质量 | 推理检查与独立评价隔离；评价语义固定 | verifier false acceptance、目标值与结构审计分歧 |
| 程序版本跨题继承 | 每代从现版本轨迹提出 patch；测试冻结 | 逐代开发/验收曲线、未见家族迁移、随机 patch 和文本记忆基线 |

正式主结果仍是跨 benchmark 自动建模准确率、消融、鲁棒性及迁移，计算量作为控制，工程案例仅补充。逐代轨迹使用开发/验收数据，不反复查看正式测试曲线以决定停在哪代。

## 8. 当前承诺与不能承诺的内容

已确定：进化对象、可修改语法、不可修改边界、内外层算法、反馈来源、数据隔离、理论检验与消融对应。v1 采用局部程序搜索与配对验收，不增加 UCB、PPO 或可训练神经路由器。

实施前还要冻结：实际原子接口与特征枚举、节点上限、候选数 M、最大代数 R、家族划分与 gate 样本量、资源限额和评价标签审计。它们是开发超参数和执行条件，不应留待看到测试成绩后决定。

对本节原始自进化机制而言，真实候选继承带来的 benchmark 改善仍未测得；v3–v8 的结果不支持把它写成成功机制。V9 已在独立 Text2Opt 确认中提高预定义 benchmark formulation accuracy，但它是后续可信编译设计，不能作为原始 DSL/进化假设的追认。全量专家语义参考和独立家族认证仍不具备，因此 objective/status accuracy 不能替代完整语义证明。理论是有假设的设计依据，不等于独立理论创新已成立。
