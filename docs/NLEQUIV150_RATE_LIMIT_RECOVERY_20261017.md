# NLEquiv-150 rate-limit diagnosis and clean restart

The first 450-cell NLEquiv run was stopped and closed without evaluation. It produced 190 terminal checkpoints: 180 completed and 10 infrastructure unavailable; 260 cells were never checkpointed. The ledger recorded 227 physical attempts. Every failed physical attempt was `HTTP 429`; there was no local environment error, malformed short output, authentication failure, model drift, or network disconnect. Two separate windows each completed exactly 60 new requests before the circuit breaker fired, identifying a provider-side request-rate window.

No evaluator file or label was opened, and no accuracy or arm comparison was calculated. Two attempted cooldown recoveries are retained as operational history, but the partially rate-limited run will not be resumed or used. This avoids treating avoidable rate-limit losses as method errors and avoids post-outcome selection because outcomes remain unopened.

The clean restart is semantically identical to the original frozen experiment. All 450 request fingerprints, pair identities, arm assignments, prompts, model, endpoint, completion cap, knowledge library, statistical gate, and concurrency-five setting are byte-identical. It uses a fresh run directory and reuses no responses. The only new component is a persistent rolling-window admission gate: at most 40 logical starts per 60 seconds with a one-second safety margin, below the empirically observed provider limit of about 60. The unused headroom covers gateway-level retries.

The rate gate has a durable SQLite ledger and a process-safe lock, survives controller restarts, and fails if its plan-bound configuration changes. A deterministic fake-clock test verifies that the third request under a two-per-ten-second policy waits beyond the window and that the reconstructed maximum never exceeds the configured limit. The clean-plan audit passed 11/11 checks, including exact semantic identity and all 450 identical fingerprints, no response reuse, labels unopened, a fresh run directory, concurrency still five, and no evaluator path.
