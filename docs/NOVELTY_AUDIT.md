# 创新性审查与主张边界

日期：2026-08-31。范围：对研究方案 v0.3 / Methodology v0.1 的批判性审查。仅做公开文献与有限源码阅读；没有运行这些方法，没有付费调用，也没有论文性能结果。

**后续用户决策覆盖本文的暂停建议：用户接受有明确问题动机、互补意义和数值证据的组合贡献，保留原 harness/进化框架。当前 v0.4 在 SEMANTIC_FEEDBACK.md 中定义差异反馈、teacher 与两级 gate 的联系。以下文献事实仍有效，不能宣称组件首次提出；但不再把“单个组件已有”作为否定框架的理由。当前状态为组合机制设计与验证准备，不是继续无限期 novelty hold。**

## 1. 结论与状态

当前“条件化 harness + 局部程序进化 + OR 验证 + 配对验收”的实现定义是明确的，但**明确不等于新颖**。已核查近邻覆盖其主要组成；现阶段不能把它写成已经成立的核心方法贡献。将 v0.3 保留为对照系统/待修订设计，不据此展开完整主方法实现和正式结果写作。

这不意味着 LLM4OR 方向被取消，也不意味着复用已有组件就是抄袭。正确引用、遵守代码许可是学术归属问题；是否新增足够的知识、算法或机制是另一个问题。新颖性并无“准确率更高即可证明”的数学判据，也不能凭有限检索证明全世界没有类似方法。

本次审查优先找直接重合和反例，不以新名称、模块数量或组合后的长标题作为差异。

## 3. 对现有理论的判定

- 将过程写成 MDP/POMDP：问题表述，不是原创贡献。
- q_{t+1}-q_t=(1-q_t)alpha_t-q_t beta_t：全概率恒等式。
- Delta J=p(g-l)：特定配对/公共前缀假设下的全期望分解。
- 配对检验、Hoeffding 界、跨代 error spending：标准统计工具及其应用。
- 在固定共享变量空间检查多面体包含关系：标准优化推理。

它们可以提高方法严谨性，不能作为“已有框架加理论即有创新”的依据。若提出新理论，应给出与实际 OR 算法相关的、更强或不同的可检验结论，并与既有假设/边界比较；不必为了形式上的三项贡献强行制造新定理。

## 4. 创新性需要怎样的证据

三种证据彼此不能替代：

1. **文献差异**：精确指出现有方法不能直接给出的表示、更新或判别步骤；说明借用了哪些组件。不是声称“别人没在这个 benchmark 跑过”。
2. **方法差异**：能用伪代码和接口指出真正新增的机制。若只需把已有框架的任务描述换成 OR、接入求解器就可实现，则优先判定为应用适配。
3. **实验价值**：证明该机制对准确率、错误定位或跨家族迁移有作用，并排除多算力、额外标签、额外工具和不公平基线。实验支持有用性，不证明历史优先权。

组合创新并非不成立：如果两个现有组件之间需要新的信息表示/信用分配/更新算法，而且有明确技术难点和证据，可以构成贡献。但“把组件放进一个图”或效果好一点不足以自动得出这个结论。

## 5. 必须加入的强对照

| 对照 | 排除什么解释 |
| --- | --- |
| AFlow/ADAS 的 OR 适配：相同模型、OR 原子工具、评价信息 | 通用 workflow search 换题目就足够 |
| AlphaOPT 加相同 OR 检查器和受控执行器 | 已有经验条件进化加更好工具就足够 |
| TriVAL / 最接近验证框架，加同样的开发优化权限 | 多阶段验证及调参即可解释增益 |
| 通用流程搜索 + 相同验证器 + 相同独立验收规则 | 准确率提升仅来自标准组件的直接组合 |
| 完整方法减去真正新增机制，保留其他信息和资源 | 所声称新机制是否具有额外作用 |
| 将结构化反馈替换成相同信息的自然语言反馈 | 改善来自信息增加，还是所提出的结构化处理算法 |

保留各基线原始协议的参考结果，并清楚标注适配版；同时报告开发搜索和测试推理成本。不要为了公平把所有方法改造成自己的方法，也不能只拿一次调用或无验证的弱系统做比较。

如果创新声称是接口/证据算法，应固定外层优化器比较该机制；如果声称新搜索算法，应给已有搜索器同样的结构化证据。原来的 2×2 adaptive/evolution 消融仍有诊断价值，但不足以排除已有方法的直接组合。

## 6. 一个值得继续审查的问题，不是已确认的新方法

保留用户的目标：提高多个 benchmark 上的自动建模准确率。收缩待研究机制为：**候选数学模型之间的可执行语义差异，能否产生有判别力的检查，并给跨题修复流程的更新提供比单一终端分数/文本反思更可靠的归因信号？**

这里的困难不是如何添加一个 verifier。多个模型可能均可执行、得到同一目标值，但具有不同的可行集合；同时一个合法等价重表述不应被误判。候选分歧可产生区分见证，但见证仅证明两个模型不同，不能自行决定谁忠实于自然语言。

若继续探索，必须具体定义并验证：

- 哪些模型关系可以比较，如何对齐变量/投影及目标，不要求所有等价表达语法相同。
- 如何产生能区分特定建模假设的检查，而不是重复已有随机 mutation。
- 哪些独立规格信息支持选择正确解释；测试参考模型仍不能进入推理。抽取有误或语义不明确时必须保留不确定性。
- 如何把检查结果转成实际不同的更新/信用分配算法，而不是只放进已有优化器的 prompt。
- 在赋予已有搜索器同等反馈后，新增更新机制是否仍提供可复现的价值。

该方向已经与 OR verification、CEGIS、active testing 和 verification-guided skill evolution 邻接。本轮**没有证明它是空白**，不取新缩写、不改成已定标题、不直接宣称新理论。VASO/A²Flow 等先例说明，“反例驱动可复用技能进化”也不能作为未经核查的替代创新。

## 7. 继续或停止标准

- 下一阶段先完成“最接近方法—新增步骤—必要证据”的对照，而不是继续堆叠角色、循环和理论名词。
- 若差异最终只是受限 DSL、更多检查或更严格验收，将其作为可复现的适配基线/工程结果，不包装成新范式。
- 若通用搜索 + 同样 OR 工具 + 同样反馈达到相同效果，不再声称具有独立算法优势。
- 若新机制只在人工注入错误上有效而不改善真实 LLM 建模轨迹，不能声称解决了 benchmark 自动建模问题。
- 不因当前思路已投入文档工作而继续扩大实现。保持正式 benchmark/付费运行未授权状态；无需重新安装或变更 ARK。

当前状态更新为 **V9 empirical effect confirmed / novelty scope still requires literature positioning**。原始 A+B 组合机制没有获得正式效果支持；V9 的选择性可信编译已在预注册 Text2Opt 确认中显示 +14.75 个百分点、59 纠正/0 退化的 benchmark formulation-accuracy 改进。该结果建立效果，不自动建立“首次”或组件级新颖性。论文必须把贡献限定为从 provenance-only 生成到 completeness-by-construction 的系统连接与实证结果，并在更新检索后再确定相对于同期 neuro-symbolic autoformulation 工作的创新边界。
