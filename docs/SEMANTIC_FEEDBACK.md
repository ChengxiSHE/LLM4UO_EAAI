## 1. A+B 为何有意义

- **A：模型验证与定位修复。** 对当前题获取条款、变量、约束及执行证据，帮助修复本题。这里的单独 A 指冻结流程的验证版本，不声称已有所有验证方法都不会学习。
- **B：跨题 harness 进化。** 利用开发反馈修改程序 H=(G,Gamma,Sigma)，在后续题上选择更合适的路径。B 可以有终端评分和文本诊断，不将它弱化成只有二元奖励。
- **简单 A+B：** 在 B 可用操作库里增加 A，并把检查结果交给通用优化器。
- **拟研究的结合：** 将候选模型间的可执行差异压缩成有来源、可重放、可定位的教学记录；以同一前缀的修复分支比较建立动作—结果对应，再更新可复用程序，并在独立题目家族上验收。

A 给 B 的价值是把笼统的成败反馈变成“哪项要求在哪个决策上被违反、修复哪个位置产生什么结果”。B 给 A 的价值是把本题的有效检查/修复经验转成下一题可执行的路由，而非每题重走全部检查。拟验证的问题是这种双向联系能否提高 benchmark 建模准确率、减少无效/有害修复，并迁移到未见家族。

理论和系统研究允许使用已有组件；不声称 A、B、teacher 或 gate 各自首次提出。最近邻包括 [AlphaOPT](https://arxiv.org/html/2510.18428)、[OR 自动验证](https://arxiv.org/html/2511.16383)、[AFlow](https://arxiv.org/html/2410.10762v3) 及 [VASO](https://arxiv.org/abs/2606.05395)。组合贡献须通过与简单 A+B 的直接比较建立，不能只超过 A 或 B。

## 2. 什么是可执行语义差异

### 2.1 统一问题级接口

固定一道题及其参数 d。模型 M_i 可有自己的内部变量 z，但必须声明到共同业务决策 x 的映射 x=decode_i(z)。记其可观察可行集合为 Fbar_i(d)。目标须统一最大化/最小化方向、货币/计量单位及已知的值还原规则；目标依赖辅助变量且无法明确还原时，标为不可比较。

第一实现范围是共享、显式对齐决策变量的 LP；域查询可覆盖已声明整数变量。一般辅助变量投影、任意双重模型、非线性重表述不能简单拿矩阵或 x 值直接比较。未支持的映射应返回 unsupported，而不是判错。对这类题仍可走原建模/验证流程，并计入端到端分母。

### 2.2 三类可执行查询

| 查询 | 操作 | 可提供的证据 |
| --- | --- | --- |
| 可行性查询 q=x | 判断固定业务决策 x 是否满足各模型的约束和变量域 | 一个模型允许、另一个禁止的决策；可指向漏约束、过约束、方向/边界/域错误 |
| 目标偏好查询 q=(x,y) | 在两个模型共同可行的方案上比较目标偏好 | 两个模型对同一对决策排序相反，或一个判平局而另一个不平局 |
| 合法情景查询 q=d' | 在预先声明允许的参数情景中求解并检查响应 | 容量、需求等改变时出现的分歧；新情景的结果必须独立求解，不能沿用旧答案 |

前两类在原题固定参数下即可进行，不必须改变用户题目。情景查询是后续扩展，只有原题语义允许该参数族且新标签可核查时使用。

**可执行语义差异**指统一接口下，存在能重放的查询，使两模型给出不兼容的确定响应。程序字符串不同不是该差异；行缩放、变量重命名、冗余约束及已声明的目标单位转换应被正确处理。

对于可行性，见证 w 满足：

    w ∈ Fbar_1(d) △ Fbar_2(d).

对于目标偏好，令 b_i(x,y)=sign(f_i(x)-f_i(y))，在同一目标方向和数值容差下比较；需记录平局。不同最优决策不一定代表不同语义，因为最优解可能不唯一。一个模型的目标乘以正数也不改变偏好；是否还需要数值单位一致，另行检查输出接口。

这里的语义只覆盖规定的可观察优化行为，不等价于完整自然语言语义或所有可能的数学等价性。

### 2.3 有限查询下的统计量及边界

在预先指定的查询集合 Q 及非负权重 w_q 上，令 C 为两模型都给出确定、可比较响应的查询。记录：

    coverage_Q = sum_{q in C} w_q / sum_{q in Q} w_q,
    D_Q = sum_{q in C} w_q * 1[response_s(q) != response_t(q)]
          / sum_{q in C} w_q.

响应不一致按查询类型定义：可行/不可行不同，或目标偏好符号（含平局）不同；数值比较使用预先冻结的尺度和容差。权重、查询生成规则和分母处理在正式测试前固定。在 Q 中没有可比较查询时 D_Q 未定义，不填零；另外报告 unknown/unsupported 率，不能通过减少覆盖率制造更低分歧。

D_Q 是候选之间的分歧诊断，不是错误率，也不是主奖励。D_Q=0 仅表示这些查询未分开候选，两个模型可能共同错误。D_Q>0 仅证明行为不同，不能直接决定哪个忠实于原文。自适应生成查询的 D_Q 也不是对全空间差异率的无偏估计。

## 3. 如何自动找出差异

### 3.1 候选来源

学生建模器生成 M_s。teacher 从原文独立抽取相关条款及局部备选表述，生成 M_t 或一个待检查条款；首次抽取不先看学生完整推理以减轻锚定，但同一模型的错误仍可能相关。候选数、检查范围和总调用上限由开发阶段确定，全部计入 token 和 solver 成本。

备选表述不是标准答案；不能以“teacher 生成”作为正确性依据。两个候选一致时仍执行固定基础检查，以应对共同错误。

### 3.2 双向可行性分歧搜索

在对齐的有界非空 LP 子类，设 F_s={x:A_s x<=b_s}、F_t={x:A_t x<=b_t}。变量上下界也作为约束行纳入。对 t 的每行 j 求：

    v_j = max_{x ∈ F_s} (a_t,j^T x - b_t,j) / s_j,

s_j 是正的预声明行尺度；先对齐变量单位，再对齐尺度。若找到源模型可行点且其残差超过容差，则获得 F_s 中违反该行的见证。交换 s/t 做反向搜索，以检测过度约束而不仅是遗漏。

找到可行的正残差点足以证明相对两表述的差异；未找到不能在任意求解状态下判相同。只有在该限定子类中，全部行取得有效上界且均不大于零，才支持包含关系。浮点实现必须报告容差与状态，不称为精确符号证明；整数域、空集、无界、辅助变量需要分别处理。

可优先检查有原文证据且结构冲突的行；这只是选择启发式。任何自适应子集没查到错误，都不能被宣传为全模型一致性证明。

### 3.3 目标排序分歧搜索

统一为最大化目标，先处理方向/单位。在共同可行的 x,y 上，寻找：

    f_s(x)-f_s(y) >= eta,
    f_t(y)-f_t(x) >= eta,
    maximize eta, eta >= 0.

线性目标与共同有界 LP 可行域使其仍为 LP。eta 大于容差给出严格反向偏好的两个方案。没有找到严格反向偏好不等于目标等价，还可能有平局差异、共同域太小或无法比较。第一版保留这些 unknown/有限覆盖情况。

## 4. 从差异到 teacher 教学记录

**2026-08-31 实现补充：** S1 暴露出 teacher 自由文本会虚构模型事实。现已实现 teacher-v2，将未认证的 `interpretation` 与可重放 `claims` 分开：模型哈希/原文引用校验后，由受控内核检查显式界、命名行和可行域蕴含；修复行需关联相反的已核验蕴含判断，未知或驳回则停止修复。原文解释不作为已证事实传递。这是修复 gate 的输入检查，不是题意真值认证。历史结果和两条 S1 错误解释的回放见 [PILOT_HISTORY.md](PILOT_HISTORY.md)。

teacher 是固定基础模型加可信求解工具的职责组合，不默认更强模型，也不训练 teacher 权重。其具体工作是：

1. **定位语义依据**：将分歧关联到原文条款、变量/约束及参数来源，检查哪个解释得到原文支持。
2. **构造可重放的对比**：记录具体决策、两方可行性/目标响应、残差、前提、版本和求解状态。
3. **提出限定修复**：指出应改的模型片段和依赖；无法判断时输出 unresolved，不强迫二选一。
4. **在开发阶段构造教学对比**：包括适用与不适用的情况，以及相同初始候选下不同修复路径的实际结果，供外层程序更新。

教学记录不是自由文本建议，至少包含：

    原文条款与定位 / 决策变量映射 / 两种建模解释
    可执行查询 / 两模型响应 / 残差或偏好反转 / 求解状态
    证据等级：数值见证、原文解释、待确认假设
    建议动作 / 许可写集合 / 依赖检查 / 不适用条件
    开发期配对结果（若有）/ 所有模型与程序版本

原文解释是 teacher 的可错判断，数值见证是相对形式化候选的证据，两者必须分开。已知最优值/标准模型仅由开发或最终独立评价器使用；正式推理 teacher 没有它们。开发评价反馈可以包含成败和错误类别，不把参考程序直接写入规则或实例记忆。

## 5. 两级 gate：当前修复与跨题更新

### 5.1 修复 gate

先检查见证可重现、变量单位/映射有效、原文依据明确。然后修复目标片段，并重检其依赖及所有仍适用的既有检查。改变了规格时旧检查的失效必须显式处理，不能静默删掉失败测试。

修复须解决支持该动作的已确认冲突；其他已保护条款的检查不得退化。若仍有无法裁定的竞争解释，保留备选或返回未解决，而非将 teacher 投票当证明。只消灭一个已知反例并不能证明修复在全空间正确；还要重跑对应的差异搜索或声明覆盖限制。

本 gate 固定，不能由进化程序修改正确性标准、关闭保护或放宽容差。其作用是过滤无证据/过范围/引入已知退化的修复，不保证消除一切语义错误。

### 5.2 进化 gate

外层仍进化 H=(G,Gamma,Sigma)，不另造新学习对象：

- G：应先检查哪个条款、生成哪种分歧查询、何时调用 teacher、回到哪层修复。
- Gamma：在什么证据组合下使用这条流程；不是“看到某 benchmark 名就用某答案”。
- Sigma：根据证据定位选择写集合与依赖重检范围。

在开发题的同一初始产物/公共前缀上，比较替代修复分支。使用独立终端评价得到每条分支的结果；检查通过数、与 teacher 的一致度或候选分歧减小均不能代替终端正确性。

候选提出器依据这些动作—结果对应修改 DSL 程序，经静态检查、开发筛选，再对冻结候选做 fresh-family 配对验收（METHODOLOGY.md 第 5 节）。原文正确模型、最优值与测试标签不得成为路由条件。主测试期间冻结程序、teacher 协议与跨题教学记忆。

配对分支的逻辑公共前缀成本对两者对称计入。API 不保证相同 seed 可复现时记录随机性，采用预定重复方案；不得把未运行的分支写成反事实效果。

## 6. 完整的反馈链与组合贡献假设

    当前程序 H_k -> 建模候选
        -> teacher 提出需核对的条款/备选表述
        -> 可信求解器生成区分见证或 unknown
        -> teacher 输出带来源的解释与限定修复建议
        -> 修复 gate -> 当前题保留版本
        -> 开发期实际配对分支与独立终端评价
        -> 更新 G/Gamma/Sigma 的候选
        -> 进化 gate -> H_{k+1}

拟贡献是一条可检验的联系：**将 OR 模型的行为差异转为局部修复和跨题流程更新共同使用的证据，使验证不只过滤答案，也改进后续验证—修复策略。** 同一证据格式跨越 teacher、修复和进化三个环节，避免从丰富诊断退化成一个总分。

若最终只有“把见证写进普通 prompt”有效，应把贡献归于反馈表示/工具及其组合，不能声称新搜索算法。若简单 A+B 在得到相同工具与反馈后达到相同效果，也应如实收缩贡献。已有的反例验证和条件进化须明确引用。

## 7. 理论如何支持实际机制

1. **区分见证的有效性**：共享变量空间、确定域及有效求解条件下，正残差点确实属于两候选可行集合的对称差；双向检查区分遗漏与过度限制。这是标准优化推导的应用。
2. **观测不足的边界**：单一目标值相同不蕴含语义相同；有限检查一致也不蕴含全空间等价；两个候选共同错误时，差异搜索无法独自提供真值。不能宣称从相互一致推导正确。
3. **更新的净收益**：原有 Delta J=p(g-l) 将新流程的触发覆盖率与最终纠错/退化对应。teacher/gate 是拟影响这些可测量量的机制，而不是公式已经证明它们有效。
4. **更新风险**：独立家族配对验收在已声明前提下控制错误接受；只使用代理标签时保证范围也仅限代理。定理不证明自然语言抽取可靠或跨域普遍迁移。

不附加无实际训练对象的 MDP/RL 模块。是否能形成进一步的 OR 理论贡献，取决于能否得到超出现有验证分析且与实现一致的结果；当前不预设。

## 8. 如何评估：从证据到最终效果

### 8.1 核心对照

| 系统 | 含义 |
| --- | --- |
| Base | 共同的基础建模与执行流程 |
| A | 固定验证—修复流程，不做跨题进化 |
| B | 跨题进化，保留合理终端/文本反馈，无本方法的差异接口 |
| 简单 A+B | 通用进化器调用相同验证工具，接收相同可用反馈 |
| A+B+对比教学 | 使用可重放、定位到条款的差异和实际分支结果组织教学 |
| 完整方案 | 对比教学 + 固定修复 gate + 独立进化 gate |

用嵌套及拆分消融分别检验 teacher、见证查询、同前缀分支、修复 gate 与进化 gate。安全/访问限制始终保留；“无 gate”只消融研究中的质量筛选，不放开任意代码或密钥访问。

额外设置两类有信息匹配的控制：给通用优化器同样的见证包；把完全相同信息转成自然语言叙述。这样可以分开“信息变多”“表示更好”和“更新机制更好”。固定外层搜索器检验反馈机制；比较搜索器时给它们相同证据。

2×2 主效应可辅以 I=Acc(A+B)-Acc(A)-Acc(B)+Acc(Base)，但准确率有天花板，I>0 不是组合有用的必要条件，更不能由它证明新颖性。最关键对照是完整方案相对简单 A+B 的收益和机制解释。

### 8.2 指标链

- **差异检测**：独立审计错误上的检出率、等价表述误报率、有效见证率、unknown/unsupported 率、检查用量。分别列 LP、整数域、目标、等价重表述与共享错误。
- **teacher**：原文解释方向是否正确、定位准确率、无依据修复建议率、未解决率。答案由隔离的参考/专家审计，不由 teacher 自评。
- **单题修复**：同初始候选的错误→正确、正确→错误、无效修改、回滚以及最终成功率。
- **跨题进化**：接受/拒绝的更新、每代开发与 gate 结果、适用边界变化、独立家族迁移。正式测试不反复查看选代。
- **论文主结果**：各 benchmark 的端到端建模准确率、强基线、配对区间、鲁棒性与实际开销。官方目标值指标与语义审计分开报告；未解决和超时不能移出分母。

teacher 与多个候选、求解器探测、分支评价及进化均有成本，分别记录开发/推理用量，保留共同 token 上限实验。初始原型主要覆盖 LP，不能用受支持子集悄悄替代全部目标 benchmark。

## 9. 已完成的本地数学检查与尚未完成项

扩展已有 `scripts/check_mechanism.py`，仍不调用 LLM。`results/mechanism_check.json` 记录了下列手工合成例子：

1. 正确模型 max x，0<=x,y<=1，x+y<=1；漏约束模型只保留边界。两者最优值均为 1，求解器找到 (1,1) 的违反见证。
2. 正确模型再误加 y<=0；最优值仍为 1，反向搜索找到被错误排除的 (0,1)。
3. 约束正数缩放并添加冗余行，双向检查在数值容差下仍包含，避免按语法差异误报。
4. 同一模型纯变量排列，在显式映射下保持可行性和目标响应。
