# 从“发现差异”到“产生有效修复”：轨迹诊断与下一阶段研究框架

更新：2026-09-13。本文基于正式 v3 运行的 73,224 条推理轨迹和 `formal-evaluation-v2` 做事后机制分析，并提出下一阶段可预注册的研究方案。分析不调用模型 API，不使用测试答案指导现有方法，也不把事后发现包装成预先提出的假设。

## 摘要

正式实验中，六种方法在 held-out 块上的公开标签代理匹配率集中在 51.831%–51.916%，`Full` 与 `SimpleAB` 完全相同，九条进化流均未改变初始程序。轨迹分析表明，无提升并非单一因素造成，而是一条连续的信号衰减链：每种方法的 12,204 个完整来源单元中只有 8,609 个获得了可继续处理的初始模型；语义流程虽然完成了 6,742 次候选—teacher 比较并发现 1,150 次可执行差异，但只生成 290 个合规 teacher packet、22 个修复请求和 4 个被接受的模型修改，且这 4 个修改没有改变公开标签代理结果。普通 solver repair 的 9,307 次 gate 接受中只有 465 次真正改变模型，约 95% 是被接受的无操作。进化阶段的全部有效候选在开发选择代理上与 incumbent 持平，两个因复杂度更低而被选中的删除候选又因 gate 基础设施缺项而未被继承。

这些轨迹支持一个修订后的研究判断：当前瓶颈主要位于**机械契约、可修复表示、预算路由和学习信号**，而不是求解器能否发现形式差异。下一版本应把引用定位、差异到编辑的映射和预算准入移入确定性控制器；让 teacher 从独立语义表示出发；扩大受控结构修复范围；用条款级测试和回归集强化修复 gate；最后在具备 formulation-level gold、按语义家族统计且具有足够不一致对的设置中重新检验流程进化。

## 1. 研究问题与证据边界

原研究问题是：可执行语义差异能否定位自然语言优化建模错误，受 gate 保护的修复结果能否进一步改进跨题复用的验证程序。正式结果回答了当前实现是否有效；轨迹诊断进一步回答效果为什么没有出现。

本文区分三类陈述：

1. **直接观测**：来自冻结轨迹、账本和修正版评价的计数。
2. **机制推断**：由代码路径与轨迹漏斗共同支持，但仍需干预实验确认。
3. **前瞻假设**：下一版本要预注册并检验，当前数据不能视为验证。

公开目标值／状态匹配仍只是代理。相同目标值不证明变量、约束、域或业务语义正确；现有 576 个独立审计单元也没有提供 formulation-level objective match。因此，下文的“纠正／退化”均指代理结果变化。

## 2. 轨迹层面的主要发现

### 2.1 方法只能作用于 70.54% 的单元

每种方法的 12,204 个单元中，只有 8,609 个形成了可求解或可继续处理的初始模型，并且这些初始模型与对应 Base 模型逐哈希一致。其余单元在初始非法输出、预算拒绝、明确 unsupported 或基础设施中断后直接返回，后续 semantic review 和 solver repair 无法恢复它们。

| Benchmark | 获得受支持初始模型 | 到达率 |
| --- | ---: | ---: |
| NL4Opt | 2,187 / 2,205 | 99.18% |
| OptiBench | 4,080 / 5,445 | 74.93% |
| IndustryOR | 630 / 900 | 70.00% |
| MAMO ComplexLP | 1,266 / 1,827 | 69.29% |
| ComplexOR | 141 / 333 | 42.34% |
| OptMATH-Bench | 305 / 1,494 | 20.41% |

这形成了一个硬性的可达性上限：现有 A/B/Full 只能修改已经生成有效稀疏 LP/MILP 的题目。尤其在 OptMATH-Bench 和 ComplexOR 上，大部分失败发生在任何验证机制启动之前。若不增加初始恢复或扩充表示能力，后续流程再复杂也无法影响这部分分母。

### 2.2 当前路由没有筛选能力，并与 token 预算冲突

所有进入程序的 8,609 条轨迹都触发 semantic review；`remaining_three_calls` 只核对调用次数，不估计剩余 token 是否足够。16,384 token 档的 2,757 个 semantic-review 节点全部报错，没有形成一个 teacher packet或接受一个修复。虽然其中 1,196 个已完成 candidate—teacher 比较，后续反馈调用仍因预算或契约失败而无法转化为动作。`Full` 在同一预算档中的后续 solver repair 也全部失败。

32,768 和 65,536 档分别只形成 137 和 153 个 teacher packet，各接受 2 个语义修复。增加预算使流程走得更远，但没有提高最终代理成绩。这说明当前问题同时包含预算准入错误和机制转化错误，不能仅靠扩大 token 上限解决。

### 2.3 语义分支的主要损失发生在反馈编译阶段

由于 A、SimpleAB 和 Full 共享相同前缀与请求缓存，三者的 semantic-review 漏斗一致。下表以一条完整方法流的 8,609 个触发节点为单位。

| 阶段 | 数量 | 相对上一关键阶段 |
| --- | ---: | ---: |
| semantic review 触发 | 8,609 | 100.00% |
| 完成 candidate—teacher 比较 | 6,742 | 78.31% |
| 发现至少一种可执行差异 | 1,150 | 比较成功中的 17.06% |
| 编译出合规 teacher packet | 290 | 比较成功中的 4.30% |
| packet 请求结构修复 | 22 | 有差异轨迹中的 1.91% |
| 修复通过 gate 并实际改模 | 4 | 触发节点中的 0.046% |
| 产生可观测代理纠正 | 0 | 接受修复中的 0% |

检测器确实找到了差异，但差异几乎没有成为可执行修复。对 2,730 个唯一且传输成功的 teacher-feedback 响应做离线契约重放，只有 153 个直接有效；2,125 个（77.84%）首先因引用来源字段或字符偏移不匹配而失败。进一步的只读反事实重绑定发现：其中 2,100 个引用文本能在题目文本或参数定义中唯一定位。若控制器自动确定字段和偏移，可额外得到 625 个合法 unresolved packet 和 39 个合法 repair packet，使物理响应层面的有效 packet 从 153 增至 817。该模拟只证明机械编译可以恢复信号，不证明恢复出的 repair 是语义正确的。

自动重绑定后，下一批主要阻塞是编辑没有对应重放证据（736 个唯一响应）、repair 缺少合法作用域或受保护点（625 个）以及正例对 teacher 不可行（69 个）。因此，修复不能止于放宽 JSON schema；需要让控制器从求解器差异中构造可验证的编辑候选，并让 LLM 只做有限的条款解释或选择。

### 2.4 teacher 被初始模型接口锚定，重要错误类别不可修复

当前 teacher 必须复制初始模型的 business-variable interface 和 objective unit，`compile_record` 还会拒绝接口不一致。这样能避免变量错位，却同时使 teacher 无法修正初始模型中遗漏的业务变量、错误的变量含义、单位和索引集合。可允许的 edit 只有 row、domain 和 objective；即使 teacher 识别到更基础的表示错误，也无法通过当前协议表达。

这会产生同源和锚定偏差：同一模型先生成候选，再在候选规定的接口中生成 teacher。可执行比较只能检测两个受同一接口约束的数学模型之间的差异，不能发现二者共同遗漏的自然语言语义。该原因由实现边界直接支持，但其实际贡献大小需要独立接口实验确认。

### 2.5 普通 repair 大量接受无操作，少量变化主要来自基础 benchmark

SolverRepair/B 的两个 repair 节点共执行 17,218 次：9,307 次通过“可求解＋受保护点”gate，但只有 465 次改变模型，即约 95.00% 的 gate 接受是无操作。最终只有 14 个代理纠正和 2 个代理退化，集中在 5 道题、4 个保守家族，而且全部来自 NL4Opt 或 OptiBench。

SimpleAB/Full 的一个 solver-repair 节点有 4,600 次 gate 接受、377 次实际改模，最终出现 16 个代理纠正、没有可观测代理退化，同样只涉及 5 道题和 4 个家族。此前的 semantic review 只改动 4 个单元且没有改变代理结果，因此 Full 的全部可观测纠正来自普通 solver repair，而非语义差异分支。

当前普通 gate 明确只保证候选仍可求解、且不破坏少量受保护点，不检查修改是否由原文条款支持。大量无操作说明 repair prompt 对多数已 optimal 模型只是重新输出原模型；少量代理改善也不能证明语义更忠实。

### 2.6 进化没有获得可学习的动作—结果信号

两代、九条 stream 共形成 18 个 stream-generation 事件。模型提出了 18 个合法候选：16 个 insert、2 个 delete；另有 2 次提案失败。14 个事件只有一个候选，2 个有两个候选，2 个没有候选。存在候选的 16 个事件中，候选在开发选择集上的最佳匹配数全部与 incumbent 相同。

选择规则在准确率持平时偏向更少节点，因此两个 delete 候选被选中。它们的 fresh gate 分别只有 22/24 和 21/24 个共同可用对；冻结协议要求全部对可用，所以二者均因基础设施缺项拒绝。其余 16 个事件没有选择不同程序。最终没有一条 stream 继承更新。

这个结果揭示了三层问题：

- 候选空间实际退化为插入／删除，未产生 guard、scope 或顺序的多样探索。
- 粗粒度诊断只统计终端代理、错误阶段和少量布尔特征，无法指出“哪个证据条件下哪种动作有益”。
- 候选插入的操作本身极少改变模型，因此在每次仅 12 道选择题的设置中几乎必然与 incumbent 持平；没有足够不一致对，统计 gate 也不可能检出质量改善。

### 2.7 评价信号不足以驱动语义学习

正式评价以公开目标值／状态为主。一份错误模型可能得到同样的最优目标；一个语义更完整的模型也可能因参考解析或输入歧义无法得分。现有重复预算和请求命名空间还是同一道题的相关观测，不能作为独立样本扩充统计功效。

因此，当前进化同时面临“动作很少改变输出”和“输出改变后评价不辨认语义”的双重稀疏性。直接增加代数、候选数或全量 API 规模，只会放大成本，不能保证增加有效学习信号。

## 3. 无提升的机制分解

对一个可选修复分支，可以把期望净收益概念性拆成：

\[
\Delta J \approx P(R)\,P(D\mid R)\,P(C\mid D)\,P(A\mid C)\,
\mathbb{E}[Y_{new}-Y_{old}\mid A],
\]

其中 (R) 是到达可修复状态，(D) 是发现相关差异，(C) 是差异成功编译为受支持修复，(A) 是修复被 gate 接受。该式用于定位信号损失，不替代严格的策略差分公式。

当前观测表明：

- (P(R)) 受初始覆盖限制，完整来源约为 70.54%，部分 benchmark 低于 25%。
- (P(D\mid R)) 并非零，至少 1,150 条轨迹出现可执行差异。
- (P(C\mid D)) 极低，只有 22/1,150 个差异成为 repair packet。
- (P(A\mid C)=4/22)，且接受的四个修复未产生代理纠正。
- 进化层面的候选激活和不一致对接近零，导致程序更新信号消失。

因此，优先级应是提高可达性、编译成功率和动作的真实影响，再研究更复杂的搜索算法。当前证据不支持把首要问题归因于“搜索代数太少”。

## 4. 修订后的方法框架

下一版本保留“可执行差异＋受控修复＋跨题程序选择”的研究主线，但重新划分 LLM 与确定性组件的职责。

```mermaid
flowchart LR
    X[自然语言与参数] --> S[独立条款语义表示]
    X --> M[候选结构化模型]
    S --> A[变量与索引对齐]
    M --> A
    A --> D[确定性差异与反例搜索]
    D --> C[证据编译器：条款绑定与合法编辑候选]
    C --> T[LLM 解释、选择或弃权]
    T --> G[条款测试＋求解＋回归 gate]
    G --> O[接受、回滚或未决]
    O --> E[按家族聚合的动作—结果诊断]
    E --> P[受限程序候选与 fresh gate]
```

### 4.1 独立条款语义表示

先从原文抽取变量、索引集合、单位、量词、目标方向和约束条款，形成不含参考答案的 typed semantic IR。候选模型与 teacher 模型分别从原文／IR 生成，之后再做受控对齐。对齐失败本身成为证据，不再强迫 teacher 继承候选的错误接口。

### 4.2 确定性证据编译器

LLM 不再生成字符偏移、哈希或可由程序计算的字段。它只返回 clause id、候选解释和有限选择；控制器负责：

- 在允许字段中唯一定位引用并生成精确偏移；
- 从求解器 witness 中枚举真正改变可行域、变量域或目标偏好的结构差异；
- 将结构差异映射成白名单 edit，并补齐依赖闭包；
- 生成和验证 positive/negative tests；
- 在任何 API 调用前完成 schema、大小和预算准入。

这既提高格式可靠性，也避免简单放宽安全检查。

### 4.3 扩展但仍受控的修复语言

在 row/domain/objective 之外，增加可审计的变量增删、单位修正、索引集修正和聚合／逐项约束切换。每类编辑都有显式前置条件、最大作用域和依赖重检，不允许任意代码或全模型自由重写。

### 4.4 证据与回归并重的修复 gate

新的 gate 至少要求：候选确实不同；目标 witness 被消除；对应条款测试通过；模型求解状态合规；既有正负例与未修改条款测试不退化；无法判断自然语言方向时弃权。普通 solver repair 也必须提交结构 diff 和来源理由，不能仅凭“仍可求解”接受。

### 4.5 预算感知路由

路由器根据请求的实际保守预留估计剩余 token，而不是只数调用次数。只有出现特定证据、且完整分支可在预算内结束时才启动 teacher／repair；否则直接保留当前模型并记录未执行原因。低预算臂应使用专门的轻量验证流程，或在预注册方案中明确不承担三调用语义链。

### 4.6 可学习的进化诊断

程序提出器接收脱敏的 typed 聚合：错误类别、证据类型、动作触发率、真正改模率、纠正／退化、无操作率、预算失败和家族覆盖。候选先通过静态“可激活性”检查；在开发选择中同时要求触发子群有效和全体非退化。质量 gate 仍使用 fresh family，但基础设施缺失的处理和最低不一致对数量要在运行前固定。

## 5. 可能提升效果的举措与优先级

| 优先级 | 举措 | 轨迹依据 | 预期作用 | 风险或控制 |
| --- | --- | --- | --- | --- |
| P0 | 保留精确异常码与阶段位置 | 4,990 个 semantic `Invalid` 在记录中丢失根因 | 使搜索和消融能识别真实瓶颈 | 日志不得包含题面、响应或密钥 |
| P0 | 确定性引用字段与偏移绑定 | 2,125/2,730 个唯一反馈首先失败于 quote provenance；2,100 个可唯一定位 | 预计把可编译 packet 提高数倍 | 唯一匹配才自动绑定，多匹配则弃权 |
| P0 | token 感知准入与分支预算 | 16k 档全部 semantic 节点失败 | 避免必然失败的调用和后续连锁耗尽 | 不依据隐藏标签决定预算 |
| P0 | no-op 预检与拒绝 | solver gate 接受中约 95% 未改模 | 降低成本并增加动作信号密度 | 等价重排需规范化后判断 |
| P0 | 初始模型恢复通道 | 29.46% 单元无法进入修复；OptMATH 到达率仅 20.41% | 扩大方法可作用的失败集合 | 严格区分格式重试与数学类型不支持 |
| P1 | 独立 semantic IR 与后置接口对齐 | teacher 被候选变量／单位接口锚定 | 检测共同遗漏、错误单位和索引 | 对齐不确定时保持 unresolved |
| P1 | 求解差异到 edit 的确定性枚举 | quote 修复后仍有 736 个证据—编辑不匹配 | 提高 actionable packet 比率 | edit 仍需原文条款选择与 gate |
| P1 | 条款级正负测试与回归 gate | 当前普通 gate 只验证可求解性 | 提高 correction/loss 比，减少错误修复 | 测试抽取本身需人工审计子集校准 |
| P1 | 异质 teacher 或多视角生成 | student 与 teacher 同模型且共享接口 | 降低同源相关错误，增加差异覆盖 | 必须加入等成本强基线并单独归因 |
| P2 | 扩充结构修复 DSL | 当前只能 row/domain/objective | 覆盖变量、单位、索引等错误 | 严格依赖闭包和最大写集合 |
| P2 | 以 typed 轨迹训练程序选择 | 现有候选全部与 incumbent 持平 | 产生与错误类别相匹配的 guard/scope 候选 | 不向提出器泄露题号或答案 |
| P2 | 预注册缺失处理与功效门槛 | 两个入选候选均因 2–3 个 gate 对缺失而失败 | 避免一次网络故障否决全部实验 | 在打开结果前补齐或冻结最小有效样本 |
| P2 | formulation-level gold 与故障注入集 | 标量代理无法识别结构语义 | 提供可学习、可解释的真实评价信号 | 专家盲审、版本和分歧仲裁要可追踪 |

“更强模型”“更多候选”“更多代数”和“更大 token”只能作为后续消融，不能列为第一优先级。现有轨迹表明，若契约和动作转化率不先提高，它们主要增加成本。

## 6. 可执行的分阶段方案

### 阶段 0：离线修复与旧响应重放

不调用 API，先完成：精确错误记录、确定性 quote rebinding、token 预算模拟、no-op 检测、分阶段漏斗导出和现有响应的离线重编译。旧响应只能用于验证编译器与诊断覆盖，不能用于重新调参后报告正式测试提升。

建议退出条件：所有本地异常均保留固定原因码；机械字段不再由 LLM 生成；16k 流程不会启动不可完成的分支；no-op 在 gate 前被识别；旧响应重放结果可由独立脚本复现。

### 阶段 1：合成结构错误的机制实验

从人工正确的 LP/MILP fixture 生成可证明的单一扰动：删除约束、过度约束、目标方向错误、变量域错误、单位缩放、索引遗漏和变量遗漏。每个样本保留原始模型、扰动模型、最小修复和可执行 witness。该阶段分别测量 detector recall、edit precision、gate false acceptance 和 repair success，先证明链路能处理已知错误。

建议退出条件：每种核心错误类型都有足够覆盖；确定性编译器不接受无 witness 编辑；对已知正确模型的回归率接近零；新增变量／索引修复在资源上限内稳定运行。

### 阶段 2：小规模、开发集限定的自然题诊断

仅从 development-propose/select 家族抽取受支持但 Base 失败或内部证据冲突的题目，比较 Base、旧 A、新 A，以及普通 repair 的强化 gate 版本。使用一个预先固定的高预算档和一个请求命名空间，避免把预算失败与方法失败混合。具体题数和 API 上限应依据阶段 1 的作用率及费用重新计算，并单独取得用户授权。

预注册的过程指标可包括：comparison 成功率、packet 编译率、actionable packet 率、实际改模率、no-op 率、条款测试通过率、代理纠正／退化和 token。只有当编译与动作漏斗显著打开，才进入程序进化实验。

### 阶段 3：具有功效的进化先导

根据阶段 2 实测的不一致对概率做 family-level 功效计算，再确定选择集和 fresh gate 的家族数。候选生成应至少包含 guard、scope、顺序和停止条件，且先检查候选在开发轨迹上是否有非零触发差异。gate 的基础设施处理必须预注册，例如在打开任何结果前重试补齐，或使用预先规定的最小可用家族数；不得看到胜负后调整样本。

### 阶段 4：独立确认实验

冻结 v2 方法、提示、预算、数据版本和评价器后，才在未使用家族上运行确认实验。主统计单位是语义家族而不是题目×预算×请求命名空间单元；重复请求用于估计模型不稳定性，以家族内聚合或分层模型处理。只有 formulation gold 主指标支持改善，才能把结果表述为建模质量提升。

## 7. 下一轮论文式实验设计

### 7.1 研究问题

- **RQ1（信号漏斗）**：从初始建模到差异、packet、repair 和 gate，各阶段损失多少潜在纠错机会？
- **RQ2（机械编译）**：确定性 provenance 与 edit 编译能否提高合法反馈率，而不增加错误编辑？
- **RQ3（语义独立性）**：独立 semantic IR 和后置对齐能否发现当前接口锚定下不可见的错误？
- **RQ4（安全修复）**：条款测试＋回归 gate 是否提高纠正／退化比，并减少无操作？
- **RQ5（流程进化）**：当动作具有足够触发率和可测结果时，typed 诊断能否产生并继承优于简单 A+B 的程序？
- **RQ6（成本）**：预算感知路由能否在保持质量的同时降低失败调用和 token？

### 7.2 前瞻假设

- **H1**：确定性 provenance 编译提高 teacher packet 的可用率，且不会改变其语义判断内容。
- **H2**：独立 semantic IR 提高对变量、单位和索引错误的检测覆盖。
- **H3**：证据与回归 gate 相对 solve-only gate 提高 family-level 的净纠正率。
- **H4**：no-op 拒绝和预算路由显著降低每个有效改模所需 token。
- **H5**：typed 诊断相对粗粒度终端计数产生更多可激活候选和不一致对。
- **H6**：在 formulation gold 上，Full-v2 超过 SimpleAB-v2；若不成立，应结论为耦合机制没有额外价值。

H1 的机械可恢复性已有事后证据，但仍需在冻结实现和未调参数据上确认；H2–H6 均未被当前实验验证。

### 7.3 比较组

| 组别 | 目的 |
| --- | --- |
| Base | 固定模型的一次结构化建模 |
| Retry/Format | 只增加合法格式恢复，隔离初始覆盖收益 |
| SolverRepair-v1 | 保留原 solve-only repair 基线 |
| SolverRepair-v2 | 加 no-op、结构 diff 和条款回归 gate |
| A-v1 | 原 semantic review，复现实验基线 |
| A-v2-Compiler | 只替换确定性 provenance/edit 编译 |
| A-v2-IR | 再加入独立 semantic IR 与后置对齐 |
| SimpleAB-v2 | A-v2 加固定普通修复，作为简单组合 |
| Full-v2 | 使用 typed 动作—结果诊断进化程序 |

采用分阶段消融，不一次展开所有因子。最关键的预设比较是 A-v2-Compiler vs A-v1、SolverRepair-v2 vs SolverRepair-v1、Full-v2 vs SimpleAB-v2。

### 7.4 指标与统计

主指标应是盲审或可执行 gold 支持的 formulation correctness，在家族层面聚合。次指标包括公开标签代理、初始覆盖率、差异发现率、packet yield、actionable yield、gate 接受率、实际改模率、纠正／退化、no-op、基础设施缺失、逻辑 token 和物理请求。

主比较使用同一家族上的配对结果；二元主指标可使用预注册的单侧／双侧精确配对检验，连续家族得分使用 cluster bootstrap 或预先确定的分层模型。多预算和多请求命名空间不能当作独立家族。效应量、置信区间、完整分母和共同可用分母同时报告；多项主假设需预先分配显著性水平或做固定校正。

### 7.5 成功与停止标准

进入下一阶段前，至少要满足：机械契约失败不再主导漏斗；候选能在足够多家族上实际改变动作；no-op 不再占 gate 接受的大多数；有足够不一致家族支撑预定检验；评价 gold 能区分结构正确与仅目标值相同。若这些条件不满足，应停止扩大 API 实验，并把研究贡献定位为失败模式和评测框架。

## 8. 论文组织方式

建议论文题目方向：**From Executable Disagreement to Reliable Repair: A Mechanistic Study of Language-to-Optimization Workflows**。

论文可按以下结构组织：

1. **Introduction**：提出 LLM 优化建模中“可求解不等于语义正确”，并把研究问题聚焦为差异证据如何转化为安全修复和可复用程序。
2. **Problem Formulation**：定义候选模型、teacher、可执行差异、typed edit、修复 gate、程序策略和 family-level 评价。
3. **Diagnostic Study of the v1 System**：报告 73,224 条轨迹的完整漏斗、预算失败、契约失败、no-op 和进化停滞。明确这是事后机制分析。
4. **Revised Framework**：介绍独立 semantic IR、确定性证据编译器、扩展修复语言、条款回归 gate、预算路由和 typed evolution。
5. **Experimental Design**：合成单错误机制集、自然 benchmark、盲审 gold、基线、消融、成本控制和家族级统计。
6. **Results**：先报机制指标，再报 formulation gold，最后报代理结果与成本；不能只展示最终平均分。
7. **Discussion**：分析同源 teacher、代理失真、支持范围、预训练污染和基础设施缺失。
8. **Related Work and Claim Boundaries**：将 solver、teacher、workflow search 和统计 gate 视为已有组件，贡献限定为证据编译、机制诊断及其受控连接的实证结果。
9. **Conclusion**：只有新实验实际支持时才声称质量提升；否则报告哪些信号转化机制有效、哪些无效。

本段是 v3 之后的历史诊断结论：当时只能主张可审计系统、失败分类、信号衰减诊断和可证伪修订方案，不能主张语义反馈、自进化或 Full 提高准确率。后续证据没有改变对 Full 的否定判断，但由该诊断导出的 V9 可信编译器已在独立 Text2Opt 确认集上提高预定义 benchmark formulation accuracy；见 `docs/V9_CONFIRMATORY_RESULTS.md`。V9 的成功不得倒写为 Full 或原始自进化机制成功。
